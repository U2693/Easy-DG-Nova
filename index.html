01

What “easy” means here

Easy is a discipline, not a dumbing-down.

Every program in this series has to earn its place by being short enough to hold in your head all at once — the same pleasure as a machine you can hold in your hand. If an episode needs a concept we haven’t covered, we stop and cover it first.

1

One idea per episode

A loop. A subroutine. A random number. Never two new tricks at once — next week’s program is allowed to use everything from the weeks before, and nothing else.

2

Short enough to type in

Most listings fit on one screen. You type them, you run them, you change a number and run them again. That loop — type, run, tinker — is the whole pedagogy.

3

Every line explained

No listing ships with a mysterious line in it. If we can’t say in plain words what a line does and why it’s there, the line comes out.

4

It has to actually run

Each program is run before it’s posted — on an emulator, and on real or simulated Nova hardware where we can — and the episode shows the output, including the parts that went wrong first.

02

Episode 01, up first

The season opener — the smallest honest program we could write.

Hello, Nova

The idea: get the machine to print a greeting on the teletype. Everything else this season — input, games, secret codes — is this program with ambitions.

Before you start: nothing. This is week one on purpose. If you can find the assembler and press Run, you have all the prerequisites there are.

  • How a Nova program starts, and where it stops (HLT)
  • Loading a character into an accumulator with LDA
  • Sending one character to the teletype, then the next
  • Why the listing ends with data, not instructions

Expected output, in full:
HELLO, NOVA!
Twelve characters. That’s the episode — and it’s enough.

hello.s — Episode 01 draft listing
; HELLO — print a greeting on the teletype
; Easy Programs for the DG Nova, Episode 01
; The whole program: load a character,
; send it out, repeat until the zero.

START:  LDA   0, PTR      ; AC0 = address of text
LOOP:   LDA   1, 0,0      ; AC1 = character at that address
        SZA   1           ; zero? then we are done
        JMP   DONE
        ; ... send AC1 to the teletype here
        ; (the episode walks through the
        ;  DOA / SKP pair line by line)
        INC   0, 0        ; point at next character
        JMP   LOOP
DONE:   HLT               ; stop, with the greeting printed

How a week works

One program, made together, on a steady rhythm.

05

What you need

Deliberately little. No Nova required in your house.

A way to run Nova code

A Nova emulator on any modern computer is enough for every episode. If you have access to real hardware, the same listings run there — the episodes note any differences we find.

An assembler & a BASIC

Assembly episodes use standard Data General Nova mnemonics (LDA, STA, JSR, DSZ…). BASIC episodes use Data General Extended BASIC — the Nova’s own dialect — detailed in §07 below. Where its syntax differs from the Microsoft BASIC most readers know, the episode flags it.

About an hour a week

Typing the listing, running it, and trying the stretch goal is designed to fit in one sitting. Falling behind costs nothing: the episodes keep, and each one recaps what it builds on.

A tolerance for octal

The Nova’s world is written in base 8. We ease in — Episode 03 is devoted to it — and by Arc II you’ll be reading 177777 as “minus one” without blinking. Mostly.

06

The machine, briefly

Data General Nova (1969)

The Nova was Data General’s first computer: a 16-bit minicomputer built around four accumulators, a famously small instruction set, and a front panel of toggle switches and lamps. It was designed to be inexpensive, compact, and understandable — a machine one person could get to know whole.

That last part is why it suits a series like this. The Nova has no hidden machinery between you and the program: memory is memory, an instruction does one visible thing, and a twenty-line listing can be a complete, honest piece of software. Easy programs aren’t a compromise on a Nova. They’re the native style.

Word size 16 bits Accumulators 4 (AC0–AC3) Numbers octal, by habit Input / output teletype first Storage in its day core memory
07

DG BASIC, in detail

The BASIC half of this blog has a proper name — and a personality.

When this page says “BASIC,” it means Data General Extended BASIC, also called Nova Extended BASIC. The earliest Novas shipped with a BASIC interpreter on punched tape; Extended BASIC followed in 1970 as Data General’s full dialect for the Nova line. Unlike Dartmouth BASIC, which compiled and ran, DG’s was an interpreter — you typed, edited, and ran in the same session, which is exactly the type-in rhythm this blog is built on.

It is based on Dartmouth BASIC, Fifth Edition — including that edition’s string variables and its powerful MAT matrix commands — and it grew up under DG’s own operating systems: DOS and RDOS on the Nova, later RTOS and AOS. Its manual, Extended BASIC User’s Manual (093-000065), was revised steadily through the 1970s; the 1978 revision is the one we work from. Data General later bought in a much larger dialect, Business BASIC, with database and multi-user record-locking features, which largely replaced Extended BASIC in commercial use — but Extended is the Nova-native BASIC, and it is ours.

Names are short — very short

A variable is a single letter, or a letter plus one digit: A, B7, S$. Two-letter names are not allowed. That one rule shapes every listing in Arcs II–IV — you plan your alphabet the way assembly programmers plan accumulators.

Arrays take one or two dimensions and always start at 1. Skip the DIM and you silently get a 10-element array — and, confusingly, a DIMmed A and an un-DIMmed A are not necessarily the same variable. We will point at that trap the first time it matters.

Numbers: two words, hexadecimal mantissa

Ordinary numbers use two 16-bit words: a sign bit, a 7-bit exponent in excess-64 form, and a mantissa stored as hexadecimal digits — good for roughly 5.4×10−79 to 7.2×1075. Double precision adds a second pair of words to the mantissa only: more accuracy, not more range. Short numbers print as decimals; longer ones switch to exponent form.

Strings, the DG way — read this before porting anything

This is where DG BASIC diverges most from the Microsoft BASIC most people learned. There are no LEFT$ / MID$ functions doing the heavy lifting. Instead you slice: A$(10) is A$ from character 10 to the end, and A$(10,20) is characters 10 through 20. Concatenation uses a comma — A$=A$,B$ appends B$ to A$ — because + is arithmetic, even on strings: "1234"+"2345" evaluates to the number 3579, and non-numeric text is simply ignored.

String variables default to 10 characters; a DIM stretches one up to 32K — which is also why there are no arrays of strings: the DIM syntax is busy declaring the string’s length. Overflow is truncated, quietly. A character that won’t type goes in by number, in angle brackets: <34> inside a literal is a double-quote.

MAT — a matrix language hiding inside BASIC

Extended BASIC kept Dartmouth’s Fifth Edition matrix suite whole. MAT statements operate on entire arrays at once — the loops you would otherwise write by hand: MAT A=A*2 scales every element, MAT A=INV(A) inverts, MAT A=DET A takes a determinant. Ready-made matrices include ZER (all zeros), CON (all ones), and IDN (the identity). No Season 1 episode needs MAT — which is precisely why it is noted here: it is the largest room in the house we are not using yet.

It talks to the machine and the operating system

DG BASIC was never sealed off from its computer. The CPU() function returns the positions of the front-panel switches — the same switches at the top of this page, readable from a BASIC program. Around it sits a small operating system in statement form: FILE and LIBRARY list directories (with wildcards), DISK reports free space, LOAD / SAVE / RENAME / DELETE manage programs, WHO lists logged-in users and MSG lets you bother them, and SIZE reports the memory your program is using.

Editing was built in, too: ERASE deletes a range of lines, ENTER reads a text file in as program lines, CARDS does the same from the card reader, and RENUMBER tidies up after an afternoon of insertions.

Error handling, ahead of its time

Two statements stand out for 1970. ON ERR THEN… traps errors inside the program instead of dying at the console, and ON ESC THEN… traps the break key the same way. RETRY re-runs the interrupted line (where CON — DG’s spelling of CONT — resumes the program), DELAY pauses, and TINPUT, governed by TIME, is an INPUT that gives up waiting after a set limit — timed input, in a line-numbered interpreter, on a machine with toggle switches.

dg-basic.bas — Extended BASIC, in its own accentManual 093-000065

20 DIM A$(14), M(2,2)
30 A$="HELLO, NOVA!"
40 PRINT A$(8,11)       REM CHARACTERS 8-11: PRINTS NOVA
50 B$=A$, " AGAIN"      REM COMMA CONCATENATES
60 MAT M=IDN            REM THE IDENTITY MATRIX
70 MAT M=M*2            REM EVERY ELEMENT, DOUBLED
80 PRINT CPU()          REM THE FRONT-PANEL SWITCHES, AS A NUMBER

What this means for Season 1: episodes 07–24 are written in this dialect. Most of it will look familiar to anyone who has seen 1970s BASIC — FOR…NEXT, GOSUB, RND, INT all behave as expected. The episodes that lean on strings (13, 14, 16, 17) are where DG’s slicing, comma concatenation, and one-letter names change the shape of the code, and each of those episodes says so up front rather than letting a Microsoft-BASIC habit fail silently.

Bring Tiny BASIC to the Nova

The suggestion: the VCF Midwest talk “Tiny BASIC: The People’s Language for the People’s Computer” tells how, when the Altair 8800 arrived in January 1975 programmable only by its front-panel switches, the People’s Computer Company answered with a BASIC ordinary people could own. Dennis Allison’s “Design Notes for Tiny BASIC” appeared in the PCC newsletter in September 1975 — a specification, not a program — inviting readers to implement it and mail their versions back. So many did that a new journal, Dr. Dobb’s, was started to print them. Tom Pittman sold his implementation for $5 while Altair BASIC cost $150.

Why it could travel to a Nova: Tiny BASIC was designed to fit in 2–3 KB and to be portable by construction. Most of the interpreter is written in a tiny purpose-built language, the IL (Interpretive Language) — an interpreter for the interpreter. To move Tiny BASIC to a new machine you do not rewrite the BASIC; you write one small IL engine in that machine’s assembly, and the same IL program runs on top. Pittman’s version was the one that kept that two-level structure intact. The Nova’s accumulator architecture suits a small engine like that well.

The language itself is genuinely tiny — in the original design: LET, PRINT, INPUT, IF, GOTO, GOSUB, RETURN, END, CLEAR, LIST, RUN; integer arithmetic; line numbers under 256. Set it beside §07 and the contrast is the story: DG Extended BASIC is a minicomputer’s full working dialect, with matrices, files, and error trapping. Tiny BASIC is the smallest honest BASIC a community could carry from machine to machine in an envelope.

Why it is not a Season 1 episode: it breaks every house rule in §01 at once. It is not one idea, not one evening, and not one page of code — it is an interpreter: a line store, a parser, an expression evaluator, and an IL engine underneath all of it. Slipping it into the roadmap as “episode 25” would be a lie about its size.

How it could work as a Season 2 headline arc — one IL-sized piece per week:

  • Week 1 — The story and the spec: Allison’s design notes, read closely.
  • Week 2 — The IL machine, implemented in Nova assembly.
  • Week 3 — Storing and listing lines: the smallest possible program memory.
  • Week 4 — Expressions: numbers, variables, and precedence on a shoestring.
  • Week 5 — Statements: PRINT, INPUT, IF, GOSUB — the language wakes up.
  • Week 6 — PRINT 2+2 on a Nova that had no business knowing BASIC this small — then readers’ own Tiny programs.

One honest caveat: no period Tiny BASIC port to the Nova is known — the Nova never needed rescuing, because DG BASIC was already there. This would be new software for an old machine, which is this blog’s charter, and it would be labelled as a port, not presented as a rediscovery. Decision point: before Season 2 planning opens. Until then, it stays here — on the record.
